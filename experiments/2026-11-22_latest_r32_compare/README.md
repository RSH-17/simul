# 최신 원본 R32와 Mixed의 같은 맵 비교

2026-11-22 조회한 yeonslay/turtlebot4-marker-slam의 main HEAD는 `d8704f64d7b9098c79a9c42dfec81e29d6d789a8`이었다. upstream README가 현재 정책으로 지정한 R32 실기 프리셋을 별도 작업공간에 빌드했다. 원본 알고리즘 소스는 수정하지 않았고 분리한 ROS 도메인의 기본 테스트 264개가 통과했다.

이 비교는 원본 R32, Mixed v1.5.1-balanced, Mixed v1.5.1-rescue360의 전체 시스템을 비교한다. 우리 두 버전의 완료 기록을 보존하고 같은 다섯 world 파일과 초기 자세에서 원본을 한 번씩 주행한다. 개발 중 본 배치 seed112601~112605, 상자5개, 벽1·상자2 마커, Original ID7·32·103, 카메라480×480·5FPS, 최대600초 시뮬 시간이다. 매칭된 world 해시와 실제 초기 위치를 검사하며 정답은 평가기에만 전달한다.

## 공통 판정

정확한 세 ID 등록, 등록한 뒤 각각 독립 실제 거리1.5m 이내 진입, 초기 TF로 고정한 좌표 변환에서 저장 마커 위치 오차0.25m 이내, 범퍼0을 함께 검사한다. 각 마커의 등록과 실제 접근, 벽·상자별 성공을 따로 집계한다. 우리 Mixed에만 있는 세 장1.3m 촬영 증거를 원본의 공통 성공 조건으로 강제하지 않는다. 우리 원래 엄격 판정은 별도 보존한다.

우리 완료 기록은 추가 촬영 증거를 기다렸으므로 전체 임무 종료 시간과 공통 세 마커 실제 접근 시각을 분리한다. 같은 카메라·맵·제한 시간을 쓰지만 주행 설정은 각 프리셋 원본이다. R32 전진0.306m/s·회전0.85rad/s·inflation0.35m, Mixed 전진0.25m/s·회전0.5rad/s·inflation0.45m이므로 알고리즘만의 효과나 동일 안전 여유에서의 속도 차이로 해석하지 않는다. 원본 자체의 collision checking과 footprint는 보존했다.

시뮬 호환 변경은 mission_time_source=ros와600초 한도이며 원본 launch도 시뮬에서 이 설정을 사용한다. 중복 RGB rosbag 저장만 껐고 독립 관측기가 실제 RGB·자세·범퍼·등록 ID를 저장한다. 실물은 사용하지 않는다.

## 실행

현재 공유 VM의 사전 설치 환경에서:

```sh
multipass exec osp-jazzy -- bash \
  /home/ubuntu/camera-aware-tools/experiments/2026-11-22_latest_r32_compare/run.sh \
  /home/ubuntu/v151-track-five-boxes5-1795247134501974510
```

실행기는 기존 두 잠금을 함께 사용한다. 진행 중 실행의 소스·설정을 바꾸지 않는다. 현재 비교 루트는 `/home/ubuntu/r32-latest-d8704f6-1795275470302489495`, 콘솔은 `/home/ubuntu/latest-r32-five1122.log`다. 완료 실패를 성공할 때까지 다시 시도하지 않는다.

보드 카드 접두사는 `r32-latest-d8704f6-track-`다. 기존 보드의 원본 전용 지도 스냅샷 처리는 예전 이름에 묶인 부분이 있어 원본의 지도 표시는 제한될 수 있다. ID·실제 이동 궤적과 완료 RGB는 별도 관측 기록으로 검증하며 최종 저장 지도를 평가한다.

원본 저장소 소스와 원시 ROS 로그는 공개 simul에 복사하지 않는다. 재현에는 upstream 접근 권한과 이 VM의 맵·헬퍼 환경이 필요하다. 공개되는 것은 우리 비교 실행기와 허용된 합성 영상·요약 결과다.

## 결과 상태

원본 실제 주행 비교 진행 중. 테스트 통과를 탐색 성공으로 세지 않으며 완료 전에는 세 정책의 우열을 정하지 않는다.
