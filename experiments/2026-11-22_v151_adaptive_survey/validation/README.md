# 새 구조에서의 사전 등록 검증

**시험장 변경 기록 (2026-11-22).** 사용자가 8780 원본 코스를 실제 시험 환경으로 지정했다. 이 문서의 소형맵 18회 자동 예약은 첫 주행 전 대기 상태에서 해제했다. 아래 등록 해시와 검증기는 보조 시험의 재현 근거로 보존한다. 현재 채택 판단에는 [원본 8780 시험장 절차](../../2026-11-22_random_exam/README.md)를 적용한다.

현재의 일곱 비교 맵에서 유망한 동결본만 **독립 맵 6개, 총 9쌍(18회 주행)**으로 넘어간다. 전체 과제 완주 여부와 기준판보다 우수하다는 통계적 근거를 각각 판정한다. 결과를 실물 기본 정책에 자동 배포하는 경로는 없다.

## 첫 단계

기존 트랙 5쌍과 새 칸막이·오목 공간 2쌍이 완료되어야 한다. 두 묶음에서 각각 벽 등록·벽 접근, 상자 등록·상자 접근, 엄격 완주 횟수 중 하나라도 감소하면 다음 검증을 보류한다. 후보에 범퍼 접촉이나 잘못 등록한 ID가 있어도 보류한다. 등록 후 접근 또는 엄격 완주 중 하나는 증가해야 한다. 이 선별 규칙은 추가 시뮬 시간을 쓰는 결정을 위한 것이다. 두 정책이 같은 결과를 낸 경우 동등성까지 입증하지는 않는다. [판정 코드](decisions.py)

## 새 맵을 만드는 절차

실제 설치한 Python 모듈·실행 파일·Nav2 설정·정책 가중치를 먼저 해시로 동결한다. 그 다음 VM에서 새로운 난수를 한 번 뽑아 여섯 seed를 결정한다. 과거 주행 이름과 seed가 겹치면 등록을 중단한다. 생성기는 방 크기와 벽 형태, 상자 위치·각도·측면, 출발 위치·방향, 세 Original ID의 부착 순서를 무작위화한다. 정책은 RGB·LiDAR·SLAM 입력을 사용하고, 평가기에서만 정답을 읽는다. [생성기](blind_fixtures.py)

| 새 배치 유형 | 마커 배치와 관찰 난점 | 정책별 실행 횟수 |
|---|---|---:|
| L자 방 | 외벽 세 곳에만 부착 | 1 |
| 사다리꼴 방 | 다섯 상자 중 세 개에 부착 | 2 |
| U자 방 | 벽·상자 혼합. 시작 시 다른 물체가 적어도 한 시선을 가림 | 2 |
| 좁은 문 | 두 공간에 마커 분산, 실제 출입구 폭 1.12–1.40m | 1 |
| 같은 상자 면 | 서로 다른 두 ID를 같은 면에 29cm 간격으로 부착, 나머지 하나는 벽 | 2 |
| 곡면 외곽 | 다각형으로 근사한 둥근 외벽 두 곳과 상자 한 곳 | 1 |

시작 전 평면 5cm 격자에서 중심 여유 42cm인 연결 구역, 각 마커 앞 0.75–1.3m·입사각 30° 이내의 가리지 않은 시선, 실제 상자·벽 면에 놓인 인쇄물 외곽을 확인한다. 생성된 SDF의 개별 흑백 셀을 다시 조합해 해당 ID로 판독한다. 이는 기하학적 가능성 검사다. 실제 도달·촬영 여부는 Nav2 주행에서 측정한다. 좁은 시선은 격자 1곳만 남아도 시험에 포함한다.

동일 쌍은 같은 SDF·바닥 메시·시작 자세·480×480 5FPS·600초를 사용한다. 첫 6쌍의 실행 순서는 번갈아 바꾸고 추가 3쌍은 같은 맵의 첫 순서를 뒤집는다. 반복은 ROS·SLAM·제어 타이밍 차이를 살피는 독립 주행이다. 물리 엔진의 난수 시드까지 같은 결정론적 재생을 보장하지 않는다.

## 과제 판정과 우열 판정

- 각 주행에서 세 ID를 정확히 등록하고, **등록 시각 이후 ID가 적힌 실제 위치 표본**에서 각각 1.5m 안에 들어와야 한다. 기존 근거리 영상 증거, 최초 좌표 변환을 고정한 저장 지도 위치 오차 25cm 이내, 잘못 보고한 ID 0개, 범퍼 0회, 600초 이내를 확인한다. 로그에서 잘못된 ID가 나타났다가 사라져도 집계한다.
- **새 구조의 과제 통과**에는 후보가 새 9회에서 모두 엄격 기준을 만족해야 한다. 특정 유형이나 반복에서 한 번이라도 실패하면 그대로 기록한다. 관측기·파일·월드 검증·출발 자세 이상으로 짝이 유효하지 않으면 해당 데이터를 성능 승패에서 빼고 판정 불가로 남긴다. 기록이 정상인 정책의 정지·시간 초과는 실패다.
- **기준판 대비 우열**은 여섯 가지 다른 맵의 첫 회차만 사용한다. 둘 다 성공, 둘 다 실패, 후보만 성공, 기준만 성공을 공개한다. 불일치 쌍의 방향에 양측 정확 이항 검정(사전 지정 0.05)을 적용한다. 두 정책 모두 9/9여도 과제 통과와 우열 미확정이 동시에 가능하다. 같은 구조의 반복 세 쌍은 표본 수를 늘리지 않는다.
- 양쪽이 모두 성공한 맵의 실제 완료 시간 차이와, 실패에 600초를 배정한 제한 시간 지표를 함께 공개한다. 두 번째 수치는 조기 실패를 속도 이점으로 만들지 않는다. 유형별 벽·상자 분모와 등록·접근, 오인식, 범퍼, 반복 일관성은 별도다. 표본이 작은 이 시험으로 모든 구조나 희귀 실패율을 보장할 수 없다. 여섯 독립 동질 시행을 가정해도 실패 0회의 단측 95% 실패율 상한은 약 39%다. 실제 여섯 유형은 의도적으로 이질적이다.

## 현재 등록과 실행

이번 R2의 여섯 물리 파일은 R2 소스를 동결한 뒤 VM에서 생성했다. 주행 전에 검증 카드 이름을 `heldout`으로 맞춰 트랙 전용 후처리를 피했고, 변경 전후 영수증에 같은 지도·순서·정책 해시를 보존했다. R2 최종 등록 해시는 `f7e497a913c92d65962922abe0d4ec8ad15943bcd1733b15956435fecc91418b`다. [등록 영수증](enrollment_receipt.json)

최초 구성의 `v151-independent-validation-1122.service`는 이 보조 비교 한 건을 감독하도록 작성됐다. 현재 서비스는 비활성 상태다. 다음 설명은 활성화 당시의 설계다. R2의 7쌍과 결과 내보내기가 끝나면 통과 여부를 확인한다. 통과하면 R2의 사전 등록 묶음을 실행한다. R2가 보류되면 R3의 공식 선별 결과를 기다린다. R3 조기 중단 또는 기준 미달 시 끝나고, R3가 일곱 쌍을 모두 통과할 때만 R3 설치본을 동결하고 다른 난수로 새로운 여섯 맵을 등록한다. R3에는 앞서 등록한 R2 지도나 결과를 재사용하지 않는다.

VM에서 다음 명령으로 현재 상태와 결과를 읽을 수 있다.

```bash
systemctl status v151-independent-validation-1122.service
cat ~/v151-independent-supervisor1122/status.json
ls ~/v151-independent-supervisor1122/results
```

각 실행은 로컬 시뮬 도메인 174에서 두 시뮬 잠금을 모두 획득한다. 시작 전 보수적인 용량 추정은 기존 완주행 다섯 중 최대 크기 × 남은 주행 수 × 1.3에 3GiB를 더한다. 공간이 부족하면 대기하고 파일을 삭제하지 않는다. 시험당 하드 상한은 네이티브 관측기 실제 40분과 후처리 시간이다. 18회 모두 시뮬 600초를 끝까지 쓰면 총 시뮬 시간은 3시간이며, 실시간 대비 0.4–0.8배라면 약 3시간 45분–7시간 30분에 준비·후처리 시간이 더해진다.

감독 기록은 `~/v151-independent-supervisor1122/`에 남는다. 진행 중에는 해당 suite의 `episodes.json`, `result.json`이 회차마다 갱신된다. 완료 시 `results/R2/` 또는 `results/R3/`에 전체 짝별 결과·유형별 집계·영상 해시와 원본 경로가 저장된다. 실패한 주행을 성공할 때까지 다시 시도하지 않는다. 서비스가 재시작돼도 완료 기록이 있는 슬롯은 건너뛴다.

독립적으로 사용하려면 검증할 두 작업공간과 해당 버전의 완결된 5+2 비교 루트가 필요하다.

```bash
bash validation/blind.sh prepare ~/new-blind-suite --screen ~/paired-screen \
  --baseline ~/frozen-baseline-ws --candidate ~/frozen-candidate-ws
bash validation/blind.sh gate ~/new-blind-suite
bash validation/blind.sh run ~/new-blind-suite
bash validation/blind.sh status ~/new-blind-suite
```

`gate`는 주행을 시작하지 않는다. `run`도 동결본과 선별 기준을 다시 검사한다. 새 지도에서 주행 결과를 본 뒤 소스를 바꾼 버전에는 새 등록이 필요하다. [실행기](validate.py) · [단일 작업 감독기](supervise.py)
