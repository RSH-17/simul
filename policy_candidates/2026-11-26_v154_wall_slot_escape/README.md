# Mixed v1.5.4 · 벽 슬롯과 갇힘 탈출 (`1.5.4-wall-slot-escape`)

`1.5.1-marker-events` 작업 공간(판단은 v1.5.1-balanced와 같다) 위에 [기준판 반복 실행 보고서](../../experiments/2026-11-26_baseline_repeat/REPORT.md) 8절의 두 제안을 넣은 후보다. **검증 결과 개선이 확인되지 않았다. 운영 정책이 아니다.** [결과](../../experiments/2026-11-26_wall_slot_escape/README.md)

```sh
bash team-sim.sh setup ~/simul-ws/wall-slot-escape --policy wall-slot-escape
```

| 변경 | 내용 |
|---|---|
| `center_wall.py` | **벽 슬롯.** 다음 조건을 모두 만족하면 벽 단계를 한 번 넣는다. 30%(600초 기준 180초)가 지났다. 벽 단계를 한 번도 하지 않았다. 등록한 ID가 3개 미만이다. 벽 관찰 후보가 있다. 슬롯은 90초 또는 벽 관찰 지점 6곳에서 끝나고, 그 뒤에는 원래의 내부 우선 규칙으로 돌아간다. 벽 선택 규칙은 바꾸지 않았다 |
| `phased_hybrid.py` | 등록한 ID 수를 일정 관리기에 넘기고, `center_wall.jsonl`에 슬롯 상태(`wall_slot`)를 남긴다 |
| `mission.py` | **갇힘 탈출.** 로봇이 0.1 m 안에 머문 채로 Nav2 경로 계획이 즉시 실패(0.6초 안)하는 일이 3번 이어지면, 기존 LiDAR 확인 후진(0.2 m)을 요청한다. 후진할 수 없으면 제자리에서 90° 돈다. 갇힌 위치는 실패 목록에 넣는다. 발생 기록은 `stuck_escape.jsonl`에 남긴다 |
| `slot_escape.py` (새 파일) | 위 두 기능의 상태 기계(`MidWallSlot`, `StuckEscape`) |

Nav2 설정, 판독 기준, 마커 접근 우선순위는 바꾸지 않았다. 마커 접근·재관찰 목표는 이전처럼 슬롯보다 먼저 처리한다. 정답 데이터는 읽지 않는다.

## 검증

- `test_wall_slot_escape.py` 8개 통과.
  - 슬롯: 시작 시각, 90초·6곳 상한, 재시작 금지, 이전 벽 단계가 있으면 건너뜀, ID 3개 등록 시 종료.
  - 탈출: 같은 자리 3회 실패 시 작동, 이동·성공 시 초기화.
  - 설치: 바뀐 파일이 위 4개뿐이고 나머지는 marker-events와 같음.
- Gazebo 20회(기준판과 같은 맵·시드). 개발 맵 7/15로 기준판과 같았고, 무작위 1/5로 기준판(3/5)보다 낮았다.
  - 슬롯은 13회 작동했다.
  - 탈출은 한 번도 작동하지 않았다. 이 20회에 갇힌 회차가 없어서 실제 효과는 확인하지 못했다.
