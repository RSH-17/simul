# 개발 주행 원시 기록 교차 점검

공개 개발 주행의 첫 체크포인트는 과거 balanced 5회, 새 balanced 2회, R2의 첫 두 회(112601, 112605)다. 같은 기록에 등록 이후 독립 거리 증거를 다시 요구한 결과는 다음과 같다.

| 지표 | 기존 판정 | 원시 기록 재점검 |
|---|---:|---:|
| 회차 전체 엄격 성공 | 5/9 | 5/9 |
| 등록 후 실제 1.5m 이내 접근 | 22/27 | 22/27 |
| 정답에 없는 ID 등록 | 0 | 0 |
| 채점 가능한 회차 | 9 | 9 |

원래 관찰자는 최신 등록 목록과 Gazebo 위치 콜백을 결합한다. 두 메시지 시각이 다를 때 등록보다 약간 이른 위치에 접근을 기록할 수 있다. 아래 세 회차는 등록 이후의 위치 표본에서도 실제 접근을 확인했다.

| 개발 회차 | ID | 등록보다 앞선 원래 접근 시각 | 원래 시각부터 새 유효 표본까지 |
|---|---:|---:|---:|
| 과거 balanced 112601 | 103 | 8 ms | 80 ms |
| 과거 balanced 112603 | 7 | 16 ms | 40 ms |
| R2 112605 | 7 | 4 ms | 20 ms |

준비된 VM에서 아래와 같이 실행한다. 각 명령은 완료되어 보고서에 실린 개발 회차만 읽는다. 출력은 JSON이다.

```bash
cd ~/camera-aware-tools/experiments/2026-11-22_v151_adaptive_survey
bash development/screen_audit.sh R2 --snapshot-first-two
bash development/screen_audit.sh R2
bash development/screen_audit.sh R3
```

9회 표본의 전체 출력은 [screen_audit_first_nine.json](screen_audit_first_nine.json)에 있다. 섹션별 합산에서는 회차가 같은 seed를 공유할 수 있으므로 이 9회의 5/9를 정책의 성공률로 사용하면 안 된다. 개별 정책 비교는 동일한 지도와 초기 자세로 짝지은 회차만 사용한다.

## 실행 프로그램과 비교 자료

- baseline, R2의 현재 VM 지문이 공개 동결 영수증과 일치했다. 소스와 설치본의 파이썬 모듈은 각각 111/111, 115/115개가 일치했다. R3 개발 단계 지문은 별도로 기록했고 116/116개가 일치했다. 세 설치본 모두 설치된 launch 및 config 파일 26개가 각자의 소스와 일치했다. 이 수치는 확인 시점의 파일 상태다.
- 과거 5회는 주행당 전체 정책 지문을 남기지 않았다. 당시 릴리스에 기록된 소스 221개, 외부 설정 2개 및 네이티브 산출물 2개가 점검 시점의 frozen balanced workspace와 일치했다. 과거 실행의 scheduler_integrity.json은 두 workspace에 있는 center_wall.py의 동일 SHA만 기록했다. runtime_parameters.json은 5개 노드의 파라미터 16개를 기록했다. supervisor_revision.json에는 관측자를 계속 사용하면서 외부 프로세스 제한시간을 변경했다고 적혀 있다. 현재 실행과 당시 실행이 다른 증거는 발견되지 않았으며, 과거의 매 회차 전체 실행 환경을 사후 인증할 수는 없다.
- 개발 기록의 월드 SHA와 실제 첫 위치를 비교하고 기존 짝지은 보고서에서 목표 종류와 설정한 출발 자세를 확인한다. 이전 회차의 월드 파일 원본과 물리 형상을 새로 복원하는 절차는 포함하지 않는다. 정책 판단에 정답이 들어가는 경로는 조사한 실행 코드에서 발견하지 못했다. 정답 자세는 평가자가 구독하고 미션 성공 및 종료 시점을 판정할 때 사용한다. 화면의 정답 표시는 별도 관측 자료다.
- 독립 판정은 등록 상태·등록 시각을 모두 만족하는 600초 이내 trajectory 표본에서 거리를 다시 계산한다. 중간 오등록·실제 카메라 형식·범퍼 수신·저장한 지도 오차도 확인한다. 개발 평가가 요구한 실시간 지도 오차 조건도 보존한다.
- 결과 확인 시 `bash development/screen_audit.sh R2 --require-eligible` 또는 R3 명령을 실행한다. 성공 종료는 기존 7쌍과 재채점이 모두 통과하고 지문·관측 기록에 이상이 없을 때만 가능하다. 불일치·미완료는 JSON 사유와 종료 코드 1로 표시된다. 이 조건을 통과하기 전에는 정책을 승격하지 않는다. 현재 가동 중인 독립 실행 감독자에는 자동 연결하지 않았다. 자동 승인 검토가 해당 감독 파일의 교체를 거부해, 이 도구는 수동 또는 후처리에서 실행한다. 이미 탈락한 후보를 재주행시키지 않는다.
