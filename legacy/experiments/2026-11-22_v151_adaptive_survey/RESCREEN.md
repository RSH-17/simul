# 후속 수정판의 사전 중단 기준

기존 다섯 트랙과 두 신규 지형은 후속 후보의 개발 선별 맵으로 쓴다. 같은 배치를 다시 사용한 결과로 일반화 성능을 추정하지 않는다.

1. 직전 r2 후보의 7쌍 비교가 모두 끝나고 기존의 사전 통과 기준을 충족하지 못한 경우에만 후속 후보를 평가한다. 동결 빌드의 개발 재생과 회귀 시험은 별도로 통과해야 한다.
2. 원본 기준 정책의 주행 기록과 지도 7개를 재사용한다. 등록 시 월드, 초기 자세·마커 배치, 기존 평가 파일과 정책 지문을 저장한다. 새 폴더의 고유 숫자 접미사로 카드·영상과 로그를 분리한다.
3. 먼저 112601·112605에서 각각 600초 한도로 한 번씩 주행한다. 두 배치는 원본 정책이 엄격 완주 조건을 충족하지 못한 경우다.
4. 두 곳 모두 엄격 완주 실패이거나 두 곳 중 한 곳에서라도 범퍼 접촉 또는 잘못 등록한 ID가 관측되면 해당 수정판의 선별을 중단한다. 일시 등록한 ID도 이벤트에서 검사한다. 미등록 영상 단서만 잡힌 ID는 오등록 수에 포함되지 않는다. 두 측정값과 중단 기록을 남긴다.
5. 이 규칙을 통과하면 같은 후보로 112801, 112802, 112602, 112603, 112604를 순서대로 실행한다. 전체 7쌍에 원래 선별 기준을 적용한다. 실험 프로그램은 별도의 블라인드 주행을 자동 실행하지 않는다. 블라인드 검증을 진행할 때에도 해당 프로그램 자체의 정책 지문·선별 통과 점검을 거친다.

Jazzy VM에서 기존 paired 루트, 새 측정 루트, 최종 검증된 별도 후보 워크스페이스를 인수로 전달한다. 새 측정 루트의 마지막 하이픈 뒤 숫자는 기존 카드와 중복될 수 없다.

    bash rescreen.sh prepare <완료된-r2-루트> <새-측정-루트> <동결된-후보-워크스페이스>
    bash rescreen.sh run     <완료된-r2-루트> <새-측정-루트> <동결된-후보-워크스페이스>

중단 시 futility_stop.json, 전체 선별 완료 시 seven_case_gate.json을 확인한다. 기존 후보 결과가 있는 회차는 재시도하지 않는다.
