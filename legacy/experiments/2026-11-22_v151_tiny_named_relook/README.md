# R4 원본 트랙 5맵 선별

8780 보드의 원본 대형 데모 트랙에서만 `Mixed v1.5.1-balanced`와 `1.5.1-tiny-named-relook`를 비교한다. 약 20.15 × 11.35m의 동일한 방, 시드별 무작위 상자 5개, 벽 마커 1개와 상자 마커 2개, 제한 시간 600초를 사용한다. 시드는 112601, 112605, 112602, 112603, 112604 순서다. 5개 모두 개발 과정에서 사용한 맵이다. 시험장 신규 독립 평가는 별도 담당자가 결정한다.

## 실행 조건

- 설치된 R4의 `tiny_named_manifest.json`, 부모 R3 지문, 수정한 파이썬 모듈의 실제 설치본, frozen balanced 실행 지문을 확인한다. 재생 결과와 Jazzy 검사 결과를 읽고 승인한 담당자가 근거 파일 및 영수증 SHA를 지정한다.
- 기존 R2·R3 개발 큐가 정상 종료, R3 조기 중단, 또는 R2 선별에 따라 R3 생략으로 끝나야 한다. 큐에 `needs_investigation`이 남아 있으면 보류한다. 소형 지도 판정과 독립 감독자의 상태는 읽지 않는다.
- 명시적으로 `run`을 호출할 때만 동작한다. ROS 도메인 174와 루프백에서 두 개의 기존 엔진 락을 모두 획득한다. 공간은 이전 완주 로그 최대 크기의 1.3배 × 남은 회차와 3GiB 예비 공간으로 확인한다. 현재 작업을 중단하거나 저장된 기록을 지우는 절차는 없다.
- 첫 두 맵에서 하나 이상의 기존 실패를 엄격 성공으로 바꾸고 범퍼와 오등록이 없어야 다음 세 맵을 진행한다. 5개를 마치면 벽·상자별 등록/접근 및 엄격 성공 합이 각각 기준판 이상이고, 접근이나 엄격 성공 지표 하나 이상이 올라야 개발 선별을 통과한다. 두 맵과 다섯 맵 어느 단계에서든 원시 근거·맵·출발 자세가 맞지 않으면 인프라 보류로 기록한다.
- 각 출발 전 1회 시도 기록을 먼저 만든다. 실행 중 프로세스가 끊겨 판정 근거를 잃으면 남은 기록을 진단해야 하며 해당 회차를 같은 이름으로 다시 실행할 수 없다. 5회 이후 추가 후보를 만들거나 순환 탐색하지 않는다.

## 사용 방법

검토한 파일들이 있는 Jazzy VM에서 실행한다. 아래 `stage`, `replay`, `jazzy`는 실제 경로로 지정한다. `inspect`와 `status`는 로봇과 시뮬레이터를 시작하지 않는다.

```bash
cd ~/camera-aware-tools/experiments/2026-11-22_v151_tiny_named_relook
bash track.sh inspect "$stage" "$replay" "$jazzy" > ~/r4-track-approval.json
bash track.sh status
```

출력된 영수증에서 릴리스 및 결과 파일 지문을 확인한다. 실제 재생과 Jazzy 검사를 통과한 경우에만 `replay_passed` 및 `jazzy_passed`를 각각 `true`로 승인하고 최종 SHA를 보관한다. `inspect`는 결과 파일 해시를 검사하고, 결과 내용의 합격 여부는 담당자가 판단한다.

```bash
sha256sum ~/r4-track-approval.json
bash track.sh run ~/r4-track-approval.json "$approved_sha256"
```

기본 결과 위치는 `~/v151-tiny-named-relook-track-112204/`다. 동시에 같은 트랙을 사용하는 작업이 있거나 디스크가 부족하면 시작 전에 종료 코드 75로 보류한다. 잠금·공간 문제가 해소된 뒤 같은 영수증으로 다시 호출하면 아직 출발하지 않은 시드부터 이어진다. `terminal.json`에 정책 실패나 인프라 보류가 이미 기록된 경우 다시 출발하지 않는다.

## 읽을 결과

- `track_comparison.json`은 완료된 원본 맵별 균형판과 R4를 함께 싣는다. 원시 궤적에서 ID 등록 뒤 1.5m 이내였는지 확인한다. 세 ID의 검출·센서 접근·고정 좌표 지도 오차 0.25m 이하·범퍼 0회·중간 오등록 없음·600초 내 종료를 검증한다. 기존 선별의 엄격 판정과 새 원시 판정이 모두 참인 경우에 엄격 성공으로 인정한다.
- `r3_vs_r4_common`은 R3 개발 기록이 있는 **동일 원본 맵**만 사용한다. 각각의 실제 실행 로그에서 수락된 최단 변이 8px 이상 10px 미만인 인쇄 단서의 ID와 요청 회전각, 익명 단서의 수락 횟수를 집계한다. 실제 등록 시각·접근 시각·접근 ID 변화와 두 회차의 성공 여부를 보고한다. 같은 ID가 나중에 등록됐다는 사실만으로 해당 요청이 등록의 원인이었거나 실제 회전이 완료됐다고 단정할 수 없다.
- `registration.json`에는 지문과 기존 비교 기록·시나리오·트랙 리소스의 해시가 들어 있다. 과거 balanced 5회의 전체 바이너리 지문은 회차별로 남지 않았다. R4는 실행 전후 실제 설치 지문과 회차 소스 지문을 확인한다.
- 원본 시뮬 대시보드는 기존 recorder와 카드를 재사용한다. 개별 카드 이름은 `v151-survey-candidate-track-m<시드>-112204` 형식이다. 카드 새로고침 실패는 별도로 저장한다. 점수는 완료된 실행 기록에서 계산한다.

로컬의 `python3 -B test_track.py`는 실제 시뮬레이션을 띄우지 않고 가짜 엔진으로 11개 항목을 검사한다. 여기에는 겹치는 실행, 저장공간 부족, 첫 두 회 탈락, 5회 종료, 중복 호출과 인프라 실패 후 재시도 방지가 포함된다.
