# 원본 R32와 Mixed의 같은 맵 비교

2026년 11월 22일, 5개 Gazebo 맵에서 세 정책을 1회씩 비교했다. **마커 세 개를 모두 등록한 회차는 R32가 4/5로 가장 많았다. 전체 15개 중 등록한 마커는 Mixed rescue360이 13개로 가장 많았다.** 등록 후 각 마커에 실제로 1.5m 이내 접근하고 지도 정확도·무충돌까지 통과한 회차는 balanced 3회, rescue360 3회, R32 2회로 확인됐다. R32 두 회차는 마지막 등록과 동시에 관측이 끝나 결과가 열려 있다. 이 다섯 맵만으로 엄격 완주율의 우열을 정할 수 없다.

|---|---:|---:|---:|

평균 종료 시각에는 시간 제한과 조기 실패가 포함된다. 확인된 완주 표본에서 세 번째 등록 후 접근 시각의 평균은 balanced 413.9초(3회), rescue360 365.0초(3회), R32 385.5초(2회)였다. 서로 다른 맵에서 완주했고 원본 속도와 inflation 설정도 달라 시간만으로 탐색 알고리즘 자체의 속도를 비교할 수 없다.

## 회차별 공통 판정

괄호에는 등록 뒤 세 번째 마커에 1.5m 이내로 접근한 실제 궤적 표본의 시뮬 시각을 표시했다. 실패 행의 시각은 임무 종료 시각이다.

| 112602 | 통과(557.0초) | 통과(456.3초) | 0개 등록, 경로 상태 복구 소진(113.3초) |

R32가 완주를 선언한 네 회차 모두 세 정답 ID를 등록했고 각 대상의 1.5m 이내를 주행 중 한 번 이상 통과했다. 이때 저장 지도 오차는 모두 6.1cm 이내였다. 112602에서는 Nav2 코스트맵이 없거나 오래됐다는 상태가 기록됐고 네 번의 상태 일시정지를 거쳐 재시도 한도를 소진했다. 코스트맵이 끊긴 하위 원인은 이 결과만으로 특정할 수 없다.

## 마지막 등록과 위치 표본의 시간 순서

원본 R32는 마지막 ID 확정과 종료를 같은 상태 메시지에 실었다. 독립 관측기의 최초 요약을 보면 R32 0/5, 등록 후 접근 8/15다. 종료 메시지를 받는 즉시 요약을 작성해 다음 실제 위치 콜백을 기다리지 않는 구현 탓에 이 네 회차 모두 마지막 ID의 접근 증거가 빠졌다. 원본 요약은 그대로 보존했다. [최초 비교 결과](comparison.json)

세 정책의 **원본 고주파 궤적 15개**에 같은 기준으로 순서를 다시 검사했다. 실제 위치 표본에 해당 ID가 있어야 하고 위치 센서 시각이 등록 시각 이후여야 한다. 종료 직후의 표본은 원래 600초 이내이고 종료 후 0.25초 이내이며 종료 전 마지막 위치에서 2cm를 넘게 움직이지 않았을 때만 허용했다. 실제로 추가 확인한 두 표본의 위치 변화는 0m였다. 모든 기준에 최초 지도 오차와 범퍼 검사도 함께 적용했다. 누락된 표본을 보간하지 않았다. 다음 비교의 관측기는 종료 시각을 먼저 고정하고, 정지 상태에서 등록 시각 이후의 실제 위치 표본을 한 번 더 수신할 짧은 창을 두는 편이 정확하다. 기록이 끝내 없으면 보류로 남긴다. 카메라 프레임 수와 평균 임무 시간에는 이 관측 대기 시간을 넣지 않는다.

## 환경과 재현 범위

원본은 yeonslay main의 2026년 11월 22일 조회 커밋 `d8704f64d7b9098c79a9c42dfec81e29d6d789a8`을 별도 작업공간에 빌드했다. 원본 테스트 264개가 통과했다. 원본 소스 열람에는 해당 저장소 권한이 필요하다. [원본 R32 커밋](https://github.com/yeonslay/turtlebot4-marker-slam/tree/d8704f64d7b9098c79a9c42dfec81e29d6d789a8) · [Mixed balanced 기준 버전](../../policy_releases/2026-11-21_mixed_camera_sync_v151) · [Mixed rescue360](../../policy_candidates/2026-11-21_v151_rescue360)

같은 world 파일 해시와 실제 시작 위치 차이 5cm 이내를 모든 회차에서 검사했다. 각 맵에는 상자 5개, 벽 마커 1개, 상자 마커 2개가 있고 카메라는 480×480·5FPS, 제한은 시뮬 600초다. 이번 배치 5개는 이전 개발에서 이미 사용했으며 새로운 구조에 대한 일반화 실험은 별도로 필요하다. 정답 좌표는 독립 평가기만 받는다. 실물 주행과 비공개 원본 소스 배포는 포함하지 않는다. [프로토콜과 소스 해시](protocol.json) · [R32 영상 5개](videos.md) · [balanced 영상](../2026-11-21_v151_track5_boxes5/videos.md) · [rescue360 영상](../2026-11-21_v151_rescue360/videos.md)

공통 완주는 세 ID 정확 등록, 등록 후 독립 실제 거리 1.5m 이내, 초기 한 번 정한 좌표 변환에서 저장 지도 오차 0.25m 이내, 범퍼 0회다. R32 자체 접근 기준은 1.9m이며 Mixed가 추가 요구하는 1.3m 영상 세 장도 별도다. R32의 전진·회전 상한은 각각 0.306m/s와 0.85rad/s, inflation은 0.35m다. Mixed의 값은 0.25m/s, 0.5rad/s, 0.45m다. 각 프리셋의 기존 안전 설정을 사용했다. R32 시뮬 시간과 한도만 원본의 시뮬 실행 방식에 맞췄고, 중복 rosbag 녹화를 끈 뒤 독립 관측기가 영상을 저장했다.

이 비교에는 단독 실행 원본 다섯 회차만 사용했다. 이전 시리즈는 설치 검사와 겹쳐 뒤 두 회차에서 Nav2 액션 준비 실패가 발생했고 마지막 회차는 외부에서 중단했다. 해당 기록은 분리 보관했다.

## 실행


현재 공유 VM의 사전 설치 환경에서:

```sh
multipass exec osp-jazzy -- bash \
  /home/ubuntu/camera-aware-tools/experiments/2026-11-22_latest_r32_compare/run.sh \
  /home/ubuntu/v151-track-five-boxes5-1795247134501974510
```

실행기는 기존 두 잠금을 함께 사용한다. 진행 중 실행의 소스·설정을 바꾸지 않는다. 완료된 단독 비교 루트는 `/home/ubuntu/r32-latest-d8704f6-1795277159207082213`, 콘솔은 `/home/ubuntu/latest-r32-clean-five1122.log`다. 초기 중단 기록은 `r32-latest-d8704f6-1795275470302489495`에 보존했다. 맵마다 한 번 실행했다.

보드 카드 접두사는 `r32-latest-d8704f6-track-`다. 기존 보드의 원본 전용 지도 스냅샷 처리는 예전 이름에 묶인 부분이 있어 원본의 지도 표시는 제한될 수 있다. ID·실제 이동 궤적과 완료 RGB는 별도 관측 기록으로 검증하며 최종 저장 지도를 평가한다.

원본 저장소 소스와 원시 ROS 로그는 공개 simul에 복사하지 않는다. 재현에는 upstream 접근 권한과 이 VM의 맵·헬퍼 환경이 필요하다. 공개되는 것은 우리 비교 실행기와 허용된 합성 영상·요약 결과다.
