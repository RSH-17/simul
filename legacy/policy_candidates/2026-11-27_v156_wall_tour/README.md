# Mixed v1.5.6 · 벽 순회 슬롯 (`1.5.6-wall-tour`)

[v1.5.5 먼 벽 슬롯](../2026-11-26_v155_far_wall_slot/README.md)에서 슬롯이 벽을 고르는 방식만 바꾼 후보다. **운영 정책이 아니다. Gazebo 주행 결과는 아직 없다.**

```sh
bash team-sim.sh setup ~/simul-ws/wall-tour --policy wall-tour
TEAM_SIM_RENDER=system bash team-sim.sh run ~/simul-ws/wall-tour 112605
```

## 왜 바꾸나

v1.5.5 20회에서 남은 벽 마커 실패는 두 종류였다([기록](../../experiments/2026-11-26_far_wall_slot/README.md)).

- 112605 0/3: 출발점에서 방 양 끝이 모두 멀었다. 슬롯은 "가장 먼 벽 하나"만 골라 서쪽 끝으로 갔고, 마커 7이 있는 남동쪽 구석에는 가지 않았다.
- 9번, 18번: 로봇은 방 양 끝을 오갔지만 긴 벽의 가운데 구간에는 다가가지 않았다.

탐색 계획 연구(FUEL, TARE, FAEP)에서도 매번 가장 좋은 한 곳만 고르면 왔다 갔다 하거나 구간을 빠뜨린다. 남은 후보 전체에 대해 방문 순서를 먼저 정하는 것이 흔한 해법이다. 이 후보는 그 아이디어를 슬롯 안에서만 쓴다.

## 바꾼 점 (v1.5.5 대비)

| 파일 | 내용 |
|---|---|
| `center_wall.py` | 슬롯이 처음 결정할 때 순회 계획을 한 번 세운다. 이후에는 계획한 순서대로 묶음을 방문한다. 순회가 끝나면 슬롯을 끝내고 내부 탐색으로 돌아간다. 먼 묶음이 하나도 없으면 v1.5.5처럼 가까운 벽을 본다 |
| `slot_escape.py` | `wall_clusters()`, `open_tour()`, `WallTour`를 추가했다. 슬롯 상한을 120초·6지점에서 180초·10지점으로 늘렸다. 여러 묶음을 돌아야 하기 때문이다 |

순회 계획은 다음 순서로 만든다.

1. **묶기:** 아직 보지 않은 벽 관찰 지점 중 로봇이 지나간 위치에서 3 m 이상 떨어진 것만 남긴다. 이것을 3 m 간격으로 묶는다. 각 묶음의 목표점은 묶음 안에서 지나간 위치와 가장 먼 점이다.
2. **순서 정하기:** 로봇 위치에서 출발해 모든 묶음을 한 번씩 지나는 가장 짧은 열린 경로를 구한다. 직선거리 기준이다. 묶음이 7개 이하면 모든 순서를 비교하고, 그보다 많으면 가까운 순서로 고른 뒤 2-opt로 다듬는다.
3. **예산 자르기:** 이동 속도를 0.18 m/s, 묶음마다 관찰 시간을 15초로 잡는다. 순서대로 더해 슬롯의 남은 시간을 넘으면 그 뒤 묶음은 뺀다.

방문 중 규칙은 다음과 같다.

- **다음 묶음으로 넘어가는 경우**
  - 한 묶음에서 2지점을 관찰했다.
  - 그 묶음에 남은 관찰 지점이 없다(이미 봤음).
  - 그 구간 이동이 예상 시간보다 30초 넘게 걸렸다.
- **고르는 관찰 지점**
  - 묶음에서 3 m 밖에 있을 때는 목표점에 가장 가까운 지점으로 간다.
  - 3 m 안에 들어오면 기존 점수(경로 거리)가 가장 낮은 지점을 본다.

v1.5.5와 같은 부분은 다음과 같다. 정답 데이터는 읽지 않는다.

- 슬롯 시작 조건: 30% 경과, 앞선 벽 단계 없음, 등록 ID 3개 미만, 벽 후보 있음
- 갇힘 탈출
- 마지막 순간의 벽 단계
- Nav2 설정과 판독 기준

## 예상되는 위험

- 슬롯이 최대 180초라 내부 탐색 시간이 줄어든다. 상자 마커 성공(v1.5.5 27/30)이 떨어지는지 함께 봐야 한다.
- 순서는 직선거리로 정한다. 벽이나 책상 때문에 실제 경로가 훨씬 길면 구간 시간 초과로 묶음을 건너뛸 수 있다.
- 지나간 위치 기준의 "먼 벽"만 묶는다. 멀리서 카메라에 이미 보인 것으로 기록된 벽 가운데 구간은 후보에 없으므로 이 변경으로는 찾지 못한다.

## 검증

- `test_wall_tour.py` 13개 통과. 확인한 항목은 다음과 같다.
  - 방 양 끝과 벽 가운데를 각각 묶음으로 만든다.
  - 가장 짧은 순서를 고르고, 근사 순서가 정확한 순서와 같다.
  - 예산을 넘는 묶음은 뺀다.
  - 관찰 후, 이미 본 경우, 시간 초과일 때 다음 묶음으로 넘어간다.
  - 180초 상한이 적용된다.
  - 설치 시 바뀐 파일이 2개뿐이다.
- 작업공간 `~/simul-ws/wall-tour`의 설치·빌드를 확인했다.
- **Gazebo 비교는 아직 하지 않았다.** 비교는 v1.5.5와 같은 조건으로 한다: GPU 렌더링, 개발 맵 5개×3회, 기준판과 같은 무작위 시드 5개. 판정 기준은 개발 맵 12/15 이상이다. 기준판은 7/15, v1.5.5는 10/15였다.
