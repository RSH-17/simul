# 실물 검증 계획

시뮬레이션은 판단 코드와 Nav2 설정이 실물과 같다. 그러나 카메라 잡음, Create3 펌웨어, 통신 지연, 바닥과 조명이 다르다. 그래서 시뮬 성공률은 후보를 고르는 데만 쓰고, 최종 정책은 실물 반복 주행으로 정한다.

## 1. 시뮬에서 후보 좁히기

1. 같은 PC, 같은 렌더링 방식에서 개발 맵 5개 × 3회 이상 돌려 기준판과 비교한다.
2. 사용하지 않은 무작위 배치(`--random-layout`) 5개 이상에서 다시 비교한다.
3. 카메라 잡음 조건(`TEAM_SIM_CAMERA_NOISE="sigma=8,blur=1,drop=0.05"`)에서 성능이 크게 떨어지는 후보는 뺀다.
4. 남은 후보 2~3개를 실물로 보낸다.

## 2. 실물 주행 조건

- 시연과 같은 조건으로 의자를 모두 빼고, 상자와 마커를 배치한다.
- 배치는 사진과 줄자로 기록한다. 마커 ID, 부착면, 높이, 로봇 출발 위치와 방향, 상자 위치를 남긴다.
- 후보마다 **같은 배치·같은 출발 자세로 번갈아** 주행한다(A, B, A, B …). 배터리와 조명 변화가 한 후보에 몰리지 않게 하기 위해서다.
- 배치는 최소 3개, 배치마다 후보별 2회 이상 주행한다.
- 구동은 `./robot.sh start`나 보드의 출발 버튼으로만 한다. 정지는 `./robot.sh stop`으로 하고, 정지 후에는 다시 지시가 있을 때만 구동한다.
- `marker-events` 작업공간이면 확정 순간 LED가 초록으로 켜지고 소리가 난다. **첫 실물 사용 때 LED·소리 동작부터 확인한다.**

## 3. 기록과 판정

| 항목 | 방법 |
|---|---|
| ID 등록 | `/mission/marker_events` 또는 `/mission/status`, `markers.csv` |
| 실제 1.5m 접근 | 실물에는 정답 위치 추적이 없다. 외부 영상으로 마커와 로봇 사이 거리를 확인하거나, 바닥에 1.5m 원을 표시한다 |
| 지도 좌표 정확도 | 저장된 `markers.csv`와 실측 마커 위치를 첫 자세 기준으로 맞춰 오차를 잰다 |
| 충돌 | 범퍼 기록과 외부 영상 |
| 시간 | 시작부터 마지막 접근까지 |

실패 회차도 지우지 않는다. 사람이 마커를 들고 있거나 배치가 바뀐 회차는 "조건 위반"으로 따로 표시한다(2026-11-18 분석 사례).

## 4. 결정 기준

1. 엄격 완주 횟수: 세 ID 등록 + 각각 1.5m 접근 + 충돌 없음
2. 그다음 벽 마커 접근률
3. 마지막으로 완주 시간

차이가 1~2회 이내라면 우열을 정하지 말고 주행을 더 한다.
